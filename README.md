# Smart Drain — Predict Why a Road Will Flood

An IoT + Machine Learning based intelligent drainage monitoring simulation system.

## 🌊 Problem Statement

Urban flooding is a critical infrastructure challenge. Traditional flood detection systems simply trigger an alarm when water level exceeds a fixed threshold, without diagnosing **why** the flooding is occurring. This prevents targeted response — maintenance crews cannot distinguish between a blocked drain, overwhelmed drainage capacity, or just heavy rainfall.

## 💡 Proposed Solution

**Smart Drain** goes beyond simple threshold-based flood detection. It uses multi-sensor data fusion, dynamic hydraulic baselines, and machine learning to:

1. **Predict** whether a road/drainage area will flood
2. **Diagnose** the probable cause (heavy rainfall, blockage, capacity exceeded, flow restriction)
3. **Localize** suspected blockage locations in multi-segment drainage systems
4. **Explain** its predictions using feature importance analysis
5. **Warn** operators with early warning lead times before flooding occurs

## 🔬 Simulation Methodology

### Hydraulic Model

The simulation uses a simplified physics-inspired water-balance equation:

```
Water(t+1) = Water(t) + Inflow(t) − Outflow(t)
```

Where:
- **Inflow** = Rainfall × Catchment Area × Catchment Factor / 3600 (mm/h → L/s)
- **Outflow** = min(Gravity Flow, Effective Capacity)
- **Effective Capacity** = Base Capacity × (1 − Blockage%)
- **Gravity Flow** ∝ √(2 × g × water head) — simplified Torricelli

### Multi-Segment Drainage

```
Road Surface → S1 (Upstream) → S2 (Middle) → S3 (Downstream) → Outlet
```

Each segment independently tracks water volume, level, and outflow. Spatial differences in water levels (ΔS1-S2, ΔS2-S3) enable blockage localization.

### Dynamic Hydraulic Baseline

Instead of fixed thresholds, the system learns the expected relationship between rainfall and flow:

```
Expected Flow = f(Rainfall, Water Level)    [Random Forest Regressor]
Flow Deviation = Expected Flow − Actual Flow
```

A large positive deviation indicates drainage obstruction.

## 📊 Dataset Generation

Synthetic data is generated by running hundreds of short simulations with varied parameters:

| Class | Rainfall | Blockage | Capacity | Description |
|-------|----------|----------|----------|-------------|
| NORMAL | Low | None | Adequate | Baseline operation |
| HEAVY_RAINFALL | High | None | Adequate | Storm conditions |
| BLOCKAGE | Moderate | 50–95% | Adequate | Drain obstruction |
| CAPACITY_EXCEEDED | Extreme | None | Reduced | Infrastructure overwhelmed |
| FLOW_RESTRICTION | Moderate | 15–45% | Moderate | Partial obstruction |

Target: 20,000 observations with realistic overlap and Gaussian sensor noise.

## 🤖 ML Models

### Model 1: Flood Risk (Binary Classification)
- **Algorithm:** Random Forest Classifier (200 trees)
- **Output:** Flood probability (0–100%) → LOW / MODERATE / HIGH / CRITICAL

### Model 2: Cause Diagnosis (Multi-class Classification)
- **Algorithm:** Random Forest Classifier (200 trees)
- **Classes:** NORMAL, HEAVY_RAINFALL, BLOCKAGE, CAPACITY_EXCEEDED, FLOW_RESTRICTION
- **Output:** Cause probabilities via `predict_proba()`

### Feature Engineering (19 features)
1. Rainfall, rainfall change
2. Water level, water level change, rise rate
3. Flow, flow change
4. Expected flow, flow deviation
5. Drainage capacity, blockage percentage
6. S1/S2/S3 water levels
7. Spatial differences (ΔS1-S2, ΔS2-S3)
8. Rolling averages (5-step window)

### Blockage Localization
Spatial analysis of segment water levels and flow patterns to identify the most likely blocked segment (S1→S2, S2→S3, or S3→Outlet).

### Explainable AI
Feature importance from Random Forest models provides transparent predictions:
```
WHY IS FLOOD RISK HIGH?
1. Water-Level Rise Rate    → HIGH CONTRIBUTION
2. Flow Deviation           → HIGH CONTRIBUTION
3. Water Level              → HIGH CONTRIBUTION
```

- Expected: High/Critical flood risk, cause = Capacity Exceeded

## ⚠️ Limitations

1. **Simplified Physics:** The hydraulic model is a simplified representation. Real deployment requires calibration with actual drainage geometry and field data.
2. **Synthetic Data:** All training data is synthetically generated. Real-world deployment requires actual sensor measurements.
3. **No Hardware:** This is a software simulation — physical sensors, controllers, and communication protocols are simulated.
4. **Single-Drain Topology:** The current model simulates a single linear drain. Real networks may have complex branching topologies.
